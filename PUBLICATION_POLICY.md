# Public Repository and Client Safety Policy

This is AGESOMA's **public** AI Engineering evidence portfolio.

## Must never be published
- API keys, tokens, passwords, connection strings, signed URLs, real customer contacts and personal data.
- Proprietary client code or internal/private repositories without explicit authorization.
- Unredacted requests, production prompts, service logs, billing terms, private architecture and credentials.
- Claims of deployment, measured quality, business impact, hiring or customer endorsements without proof.

## Public showcase requirements
- Use synthetic or explicitly licensed data, sanitized configs and `.env.example`.
- Include security assumptions, test commands, known limitations and citations to external references.
- Respect upstream dependency and source-code licenses.
- Report real test metrics only with reproduction instructions; label simulated evaluations.
- Keep engineering implementation separate from the corporate public case-study description where appropriate.

## Release checklist
- [ ] Repository scan for leaked secrets and personal data.
- [ ] Rights/license and customer publication permission reviewed.
- [ ] Demo endpoints use least privilege and no real-world side effects.
- [ ] Test/CI evidence link, actual dates and commit SHA.
- [ ] Explicit status label and truthful limitations.

## Public service-offer claims

- Label a service package as `Proposed offer` until a relevant original technical implementation and independent acceptance evidence justify stronger claims.
- Keep separate: (1) advertised freelancer request; (2) LinkedIn job skill requirement; (3) original AGESOMA implementation/CI; (4) authorized client deployment; (5) verified customer outcomes. Never equate these categories.
- Every service page should link to dated, public demand evidence in [MARKET_SIGNAL_WATCHLIST.md](MARKET_SIGNAL_WATCHLIST.md), with sample and freshness limitations.
- Prices, business metrics, SLA, conversion gains and client names must not be invented or implied from advertised budgets.
- Use documented human approvals for privileged CRM writes, customer messages, scheduling or payment actions; no public demo may perform unsafe external side effects.
- Do not publish Raphael's private GitHub learning tracker, personal resume, interview answers/scores, contact data or the private Google Drive URLs.
- Project status may advance only with source/PR, exact-SHA tests, documented limitations and deployment/authorization proof if claimed.
