# InstantWork — Outcomes and Evidence

**Public portfolio status (2026-11-07):** The primary execution platform is the **private** `AGESOMA/InstantWork` repository. It remains a laboratory/preproduction product. This register describes what the connected codebase contains and what has **not yet been independently verified**. It is not a claim that a buyer's requested work has been delivered.

## Current capability register

We organize the public showcase around **business outcomes and completion evidence**, not lists of AI models, frameworks or features. A capability is worth presenting when it turns a scoped business request into an inspectable result; unfinished integrations remain clearly labeled. The mission is to expand a **single reusable execution platform** across new classes of work without claiming they are all already supported.

| Capability | What exists in InstantWork | Verifiable delivery boundary | State |
| --- | --- | --- | --- |
| Task interpretation and company planning | Local owner-first business coach, curated task categories and draft/delegation policy modules | Drafts and plans are not completed external work | **Local code present; deployment unverified** |
| Internal support/lead/appointment intake | Internal work-kind validation and read-only planning modules; a three-case fictional work-sample harness is proposed in a private review PR | The work-sample CI has failed; the three scenarios are **not validated** and no messages, CRM records or appointments were created | **Under test / blocked CI** |
| Open Instinct agent foundation | Pinned upstream Git submodule and a restricted Pi workcell/native bridge | The workcell's documented tool registry is empty and draft-only; the presence of upstream code does not establish autonomous execution | **Laboratory; restricted** |

| General-purpose service execution | Planned orchestration through composable, audited open-source adapters and permissions | Each new job category requires actual source, tests, authorized provider actions and independent verification | **Strategic objective, not yet a delivered capability** |

**Positioning rule:** Lead with the work requested, the work actually done and the verified outcome. Describe Open Instinct, CRM, code, model providers and other infrastructure as supporting implementation details. Avoid visionary scale claims, imitation of investor language, invented enterprise metrics, client logos or ROI. **Important:** This is a private-source product. A public reader cannot independently inspect the source or CI behind a private repository. Until there is a **sanitized, reproducible public demonstration** and approved evidence for the exact revision, the capability must remain marked as private and not independently verifiable. No customer results, commercial delivery, cost saving or external automation is claimed.

## How a new case appears here

Each work sample is derived from a legitimately accessible technical requirement and follows:

**Research public requirements → scope and classify work → implement inside InstantWork → test and audit the exact revision → publish safe evidence here.**

A published case includes:

1. **Problem and expected artifact:** business need, concrete deliverable and acceptance criteria, without buyer identity or private material.
2. **Actual executor:** the InstantWork version and approved open-source adapters used; no parallel engine silently relabeled as InstantWork.
3. **Workload origin:** synthetic/authorized inputs, sample size and whether evaluation examples are authored or independently held out.
4. **Measured technical behavior:** outputs and errors reproduced by code, with public-safe tests and commit/CI attestation where available.
5. **Permissions and risk:** tenant access, owner approvals, provider receipts, security/abuse constraints and unimplemented gates.
6. **Business effects:** observed time/cost and customer acceptance **only when genuinely measured**; hypothetical ROI is separately labeled as a model.

### Case status ladder

| Status | Allowed interpretation |
| --- | --- |
| `SCOPED` | Work request understood; no implementation proven |
| `LOCAL_SIMULATION` | Real InstantWork code processed fictional inputs; no client action |
| `QA_VERIFIED` | Tests on the exact revision and defined sandbox behavior verified |
| `AWAITING_APPROVAL` | Real action needs a specific customer's authorization |
| `EXTERNAL_ACTION_VERIFIED` | Authorized provider action has an independently checked receipt |
| `CLIENT_ACCEPTED` | Client acceptance confirmed and disclosure authorized |
| `FAILED` / `BLOCKED` | Failed checks or missing access, integration, rights or reliable evidence |

**"Completed work" requires customer-approved scope and independent external evidence** where applicable, not merely a passing test, AI text, a screenshot or a merged PR.
