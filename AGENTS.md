## Daily project and weekly market operating rules

1. Revalidate the original Upwork, Workana and LinkedIn examples each Monday inside the existing daily AI Engineering + AGESOMA PROJECTS routine; document links, dates, sample size, type of hiring signal and confidence. Market demand is not proof of AGESOMA revenue.
2. Keep **one active flagship build** across as many weeks as required. Each week select a market-backed, independently checkable milestone; BUILD creates a bounded original change, AUDIT independently tests and remediates it. Do not start a new project to fill a calendar slot.
3. A service is a PROPOSED OFFER until supporting, relevant, inspected code/tests exist; a public demo remains DEMO, not paid customer implementation. No invented client logos, testimonials, ROI, deployment, hiring or uptime.
4. Code should start from a deterministic baseline, use typed APIs, real authorization, synthetic/approved data, idempotency, error/timeout handling and tests. Add LLM/tool calling only where scope requires it. No unapproved real WhatsApp sends, CRM changes, payment actions or customer-data ingestion.
5. Work in reviewable branches/PRs. **Never auto-merge**; don't edit private/legacy/unauthorized repos; don't publish contact details, personal interview scores, private resume, secrets or customer content.
6. Report tests, CI, evaluation, quality, cost and latency ONLY when observed and linked to the exact commit/test environment. Name missing evidence and next acceptance gate.
7. When verified skills change, update the recruiter-safe public case and [AIEngineer recruiter guide](https://github.com/RiverThreeR3/AIEngineer/blob/main/docs/RECRUITER_GUIDE.md) only with compatible evidence; do not copy code or publish private resume.
8. Refresh offer priority against evidence; edit [SERVICES.md](SERVICES.md) and [MARKET_SIGNAL_WATCHLIST.md](MARKET_SIGNAL_WATCHLIST.md) through PRs, documenting why the ranking changed. Never claim a statistical platform-wide rank from a small sample.

## Deliverable gate

A published case must provide problem, authentic scope, original implementation link, fixed inputs and acceptance tests, reproducible run commands, measurable improvements where available, authorization/privacy controls, license and honest limitations. Controlled deployment is only claimed after independent verification.
