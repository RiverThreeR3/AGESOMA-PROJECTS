## Daily project and weekly market operating rules

1. **Daily:** inspect up to three recent public Upwork and up to three Workana briefs as read-only **technical scope inputs** (when accessible), noting URLs, dates, requested artifact, job type and sampling limits. Keep LinkedIn career scouting separate. Consider the full range of eligible enterprise work, not just CRM/agent demos. For a brief, select one of EXISTING_CAPABILITY, OPEN_SOURCE_ADAPTER, NEW_CAPABILITY, RESEARCH_ONLY or REJECT; record feasibility, license and why. Select one bounded reusable capability/defect to implement, simulate or audit using the **single InstantWork platform in the private primary repository**. A daily review with no safely verifiable work must report BLOCKED rather than fabricate a project. Existing standalone Knowledge API demonstrations remain separately labeled and are not falsely attributed to InstantWork. Public market briefs never authorize outreach, real execution or client claims.
2. Keep **one primary operating product, AGESOMA/InstantWork**, across as many weeks as required. Each day runs the complete **RESEARCH → IMPLEMENT → AUDIT** cycle: select a supported public requirement, build or repair one bounded capability in InstantWork, then independently test and review that same change at its exact SHA. Update this public evidence portfolio only after verification. Do not start a new project to fill a calendar slot.
3. A service is a PROPOSED OFFER until supporting, relevant, inspected code/tests exist; a public demo remains DEMO, not paid customer implementation. No invented client logos, testimonials, ROI, deployment, hiring or uptime.
4. Code should start from a deterministic baseline, use typed APIs, real authorization, synthetic/approved data, idempotency, error/timeout handling and tests. Add LLM/tool calling only where scope requires it. No unapproved real WhatsApp sends, CRM changes, payment actions or customer-data ingestion.
5. Work in reviewable branches/PRs. The private `AGESOMA/InstantWork` is explicitly authorized as **primary** for the combined daily engineering routine, with AGESOMA-account permission checks; all other private/legacy repos remain off-limits. **Never auto-merge**; never publish private source, contact details, interview scores, private resume, secrets or customer content.
6. Report tests, CI, evaluation, quality, cost and latency ONLY when observed and linked to the exact commit/test environment. Synthetic work-sample metrics must show real code execution and fixture provenance; **modeled** handling time, cost and ROI must be labeled as invented assumptions, never observed client results. Name missing evidence and next acceptance gate.
7. When a capability is *actually executed inside InstantWork* and validated, update [CAPABILITIES.md](CAPABILITIES.md) with the work-order status, exact executing source/revision, tests/receipt and limits. Add a public-safe case description only when evidence allows; do not feature standalone work done outside InstantWork. The separate [AIEngineer recruiter guide](https://github.com/RiverThreeR3/AIEngineer/blob/main/docs/RECRUITER_GUIDE.md) may link individually attributable work without copying private code or personal records.
8. Refresh offer priority against evidence; edit [SERVICES.md](SERVICES.md) and [MARKET_SIGNAL_WATCHLIST.md](MARKET_SIGNAL_WATCHLIST.md) through PRs, documenting why the ranking changed. Never claim a statistical platform-wide rank from a small sample.

## Deliverable gate

An **active showcase** case must originate exclusively in **AGESOMA/InstantWork**, provide problem, authentic scope, actual execution mode, public-safe exact-SHA evidence, fixed synthetic inputs and acceptance tests, reproduction when legally possible, observed results separately from modeled business savings, privacy/authorization controls and limitations. Standalone code or experiments belong only in the **historical archive**, visibly excluded from InstantWork capability and delivery claims. A private PR or CI run is not necessarily accessible to public reviewers; provide sanitized reproductions rather than disclosing private source. Controlled deployment is claimed only with independent provider and client verification.
