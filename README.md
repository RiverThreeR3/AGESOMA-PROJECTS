## Public case-study standard

When a project passes review, publish:
1. Real business problem, scope and acceptance criteria.
2. Original architecture, sequence diagram and design trade-offs.
3. Reproducible instructions and sanitized configuration.
4. Test and evaluation methodology, dataset provenance, metrics, failure cases and baseline comparison.
5. Latency, cost and operational constraints where measured.
6. Threat model, authorization boundaries and data protection decisions.
7. Real demo / video / deployment (clearly labeled), with actual project status.
8. Clear attribution to dependencies and licenses.

**Public-only policy:** no credentials, internal client data, proprietary repositories, unapproved customer testimonials, private architecture or fabricated metrics. See [PUBLICATION_POLICY.md](PUBLICATION_POLICY.md).
